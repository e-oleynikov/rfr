# Repository Guidelines

## Структура проекта

Rangiffler состоит из серверных Java-модулей на Gradle и отдельного интерфейса на React/TypeScript:

- `rfr-auth/`: сервер авторизации OAuth/OIDC на Spring Boot. Шаблоны Thymeleaf и статические ресурсы находятся в `src/main/resources/`.
- `rfr-api/`: GraphQL API на Spring Boot. Контроллеры, сервисы, репозитории и JPA-сущности расположены в `src/main/java/io/student/rangiffler/`.
- `rfr-gql-client/`: интерфейс на Vite. Каталоги `src/components/`, `pages/`, `hooks/`, `api/` и `types/` содержат компоненты и логику работы с данными; ресурсы находятся в `src/assets/` и `public/`.
- `rfr-e2e/`: Java-тесты в `src/test/java/`, настройки JUnit в `src/test/resources/`.

Схемы GraphQL находятся в `rfr-api/src/main/resources/graphql/`. Изменяйте схемы, не редактируйте сгенерированные классы в `build/generated/`. Изменения БД оформляйте миграциями в `src/main/resources/db/migration/` соответствующего сервиса.

## Сборка и локальный запуск

Используйте JDK 25 и Gradle Wrapper из репозитория. Команды из корня проекта:

- `./gradlew build` — сборка Java-модулей и запуск настроенных тестов.
- `./gradlew :rfr-auth:bootRun` — запуск авторизации на порту 9001.
- `./gradlew :rfr-api:bootRun` — запуск GraphQL API на порту 8081.
- `./gradlew :rfr-e2e:test` — запуск набора тестов JUnit.
- `./gradlew :rfr-e2e:test --tests '*SimpleTest'` — запуск отдельного тестового класса.

В каталоге `rfr-gql-client/` выполните `npm ci`, затем `npm run dev` для запуска на порту 3001. Команда `npm run build` проверяет TypeScript и собирает приложение, `npm run lint` запускает ESLint; предупреждения недопустимы.

## Стиль кода и именование

Следуйте стилю соседнего кода: в Java обычно используются отступы в два пробела, в TypeScript — четыре. Имена Java-классов и React-компонентов пишите в PascalCase, методов и переменных — в camelCase, хуков — по шаблону `useXxx`. Компоненты обычно размещаются в отдельных каталогах с файлом `index.tsx`. Отдельный форматтер Java не настроен; интерфейс проверяется ESLint и TypeScript.

## Тестирование

Используются JUnit Jupiter 6, Playwright Java и Allure. Называйте классы по шаблону `*Test`, проверяйте изменённое поведение содержательными утверждениями. Сейчас есть только демонстрационный тест; минимальный процент покрытия и команда тестирования интерфейса не настроены. Для браузерных сценариев необходимы запущенные сервисы и MySQL. Параллельный запуск отключён.

## Коммиты и pull request

В истории встречаются краткие описания действий (`Resize map component`) и префиксы вроде `docs:`. Делайте коммиты небольшими и тематически связанными. В PR описывайте изменения поведения, прикладывайте ссылки на задачи, команды проверки и результаты. Для изменений интерфейса добавляйте скриншоты.

## Локальная конфигурация

Запускайте MySQL перед авторизацией, API и интерфейсом. Значения `.env` берите из README интерфейса; согласовывайте адреса перенаправления. Перед использованием изучите `localenv.sh`: скрипт останавливает и удаляет все Docker-контейнеры на машине. Не добавляйте реальные пароли и токены в репозиторий.
