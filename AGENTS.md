# Правила проекта Rangiffler

## Структура проекта

Сейчас Rangiffler использует монолитный `rfr-api` с частично реализованной логикой и моками, отдельный сервер авторизации и интерфейс на React/TypeScript. Пользователи, дружба и страны работают через БД. Фотографии, лайки и статистика используют моки; изменения фотографий не сохраняются в БД. Микросервисная архитектура — направление дальнейшего развития, а не текущее состояние.

Перед изменением модуля прочитайте его инструкции. Они дополняют общие правила этого файла.

| Модуль | Назначение | Порт | Инструкции |
| --- | --- | --- | --- |
| `rfr-auth` | Сервер авторизации OAuth/OIDC на Spring Boot | `9001` | [AGENTS.md](rfr-auth/AGENTS.md) |
| `rfr-api` | GraphQL API на Spring Boot, endpoint `/graphql` | `8081` | [AGENTS.md](rfr-api/AGENTS.md) |
| `rfr-gql-client` | Интерфейс на React/TypeScript и Vite | `3001` | [AGENTS.md](rfr-gql-client/AGENTS.md) |
| `rfr-e2e` | Java-тесты на JUnit и Playwright | Собственного порта нет | [AGENTS.md](rfr-e2e/AGENTS.md) |

MySQL доступен локально на порту `3306`; схемы — `rangiffler-auth` и `rangiffler-api`.

Схемы GraphQL находятся в `rfr-api/src/main/resources/graphql/`. При их изменении обновляйте связанные операции и типы. Не редактируйте сгенерированные файлы вручную, в том числе классы в `build/generated/`. Изменения БД оформляйте миграциями в `src/main/resources/db/migration/` соответствующего сервиса.

## Сборка и локальный запуск

Используйте JDK 25 и Gradle Wrapper из репозитория. `./gradlew build` собирает Java-модули и запускает настроенные тесты, включая E2E; для них нужно подготовленное окружение.

`./gradlew runAll` запускает оба бэкенда: `rfr-auth` на порту `9001` и `rfr-api` на `8081`. Задача вызывает Gradle Wrapper с параллельным выполнением двух `bootRun` и двумя рабочими потоками. Логи выводятся в общий терминал; для остановки обоих серверов нажмите `Ctrl+C`. Перед запуском подготовьте MySQL через `bash localenv.sh`; интерфейс запускается отдельно.

Команды запуска и проверки отдельных модулей находятся в их `AGENTS.md`. Подробная подготовка окружения и примеры использования — в README соответствующего модуля.

`./gradlew e2eTest` запускает только тесты модуля `rfr-e2e`, без тестов бэкендов и автоматического запуска окружения. Требования к запуску описаны в [инструкциях E2E](rfr-e2e/AGENTS.md).

## Стиль кода и именование

В Java обычно используются отступы в два пробела. Имена Java-классов пишите в PascalCase, методов и переменных — в camelCase. Отдельный форматтер Java не настроен. Соглашения интерфейса описаны в [инструкциях rfr-gql-client](rfr-gql-client/AGENTS.md).

## Проверки изменений

Проверяйте изменённое поведение содержательными утверждениями. При исправлении ошибки по возможности сначала добавляйте воспроизводящий тест: подтвердите падение по ожидаемой причине до исправления и прохождение после него. Если это невозможно, объясните ограничение и способ проверки.

Для Java запускайте относящиеся к изменению тесты и сборку затронутых модулей. Для изменений GraphQL и миграций проверяйте совместимость и поведение в объёме изменения. Конкретные команды и требования к окружению смотрите в инструкциях модуля.

Изменения серверов и интерфейса могут требовать E2E-проверок. Перед их запуском прочитайте [инструкции rfr-e2e](rfr-e2e/AGENTS.md), даже если тестовые файлы не меняются: тесты создают и удаляют данные в настроенной БД.

## Коммиты и pull request

В истории встречаются краткие описания действий (`Resize map component`) и префиксы вроде `docs:`. В PR описывайте изменения поведения, прикладывайте ссылки на задачи, команды проверки и результаты. Для изменений интерфейса добавляйте скриншоты.

## Разрешения и запреты

- Для работы над задачами разрешены запуск локальных бэкендов (`runAll` и `bootRun`), интерфейса (`npm run dev` и `preview`), MySQL через Compose или `bash localenv.sh`, сборка, линтер и тесты проекта без дополнительного согласования. Это относится к локальному окружению; общие среды требуют отдельного согласования.
- `git push` запрещён. Оставляйте коммиты локальными; не обходите запрет через RTK, параметры Git, скрипты, API или другие инструменты публикации.
- `rm`, `grm` и другие способы безвозвратного удаления файлов и каталогов запрещены. Вместо удаления перемещайте объект в `.<имя>.<время>.bak`, не перезаписывая существующие копии. Не включайте резервные копии в коммиты; в отчёте перечисляйте оставленные копии. Не обходите запрет через скрипты или другие инструменты.
- Командные правила находятся в [.codex/rules/project.rules](.codex/rules/project.rules). Они разрешают конкретные префиксы команд, учитывают прямой запуск и RTK, но не являются универсальной защитой от произвольного кода. Не расширяйте разрешения на весь shell, Docker или Git ради обхода ограничений.

Проектные правила Codex загружаются при старте доверенного проекта; после изменения файла правил перезапустите Codex. Настройки текущей песочницы и управляемые ограничения среды сохраняют силу.

## Локальная конфигурация

Запускайте MySQL перед авторизацией, API и интерфейсом. `bash localenv.sh` запускает сервис MySQL через Docker Compose и ожидает успешного healthcheck. Значения `.env` берите из README интерфейса; согласовывайте адреса перенаправления.
