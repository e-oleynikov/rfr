# Автопроверка исходников

`validate_changes.py` обслуживает синхронные события `PreToolUse` и `PostToolUse` Codex для `Bash`, `apply_patch`, `Edit` и `Write`.

Перед инструментом сохраняются хеши исходников, после его выполнения сравнивается содержимое. Поэтому учитываются правки через patch и shell, новые файлы и перенос исходника в `.bak`, в том числе при неуспешном завершении инструмента. Неизменённый код не проверяется повторно. Одновременные проверки используют блокировку.

## Что выполняется

- Для изменённых `.java` в `src/` модулей auth, API и E2E — `./gradlew :<модуль>:compileTestJava --console=plain`. Несколько изменённых Java-модулей проверяются одним вызовом Gradle.
- Для изменений `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.css`, `.scss`, `.html` и `.json` внутри `rfr-gql-client` — `npm run lint` и `npm run build` из каталога интерфейса.
- Каталоги `build`, `dist`, `node_modules` и скрытые каталоги исключены. Правки Markdown не запускают компиляцию. Зависимости автоматически не устанавливаются, сервисы и E2E-тесты не запускаются.

Нужны установленные JDK 25 и зависимости npm. На macOS JDK 25 выбирается через `/usr/libexec/java_home`; если npm отсутствует в PATH, проверяется установленный Node.js 24 в `~/.nvm/versions/node/`. Установка инструментов hook не выполняется.

Каждая команда ограничена 150 секундами. Вывод stdout и stderr сохраняется в `.codex/hook-state/logs/`, а код завершения, выдержка и путь к полному журналу возвращаются агенту через `hookSpecificOutput.additionalContext`. Ошибки и ограничения окружения сообщаются явно. При изменении исходников во время проверки результат помечается как промежуточный; скрытых повторов до успешного результата нет.

Компиляция E2E подтверждает только компиляцию. Доказательство работы теста по-прежнему требует фактического выполнения Gradle-задачи `test`.

## Подключение

Локальный `.codex/hooks.json` уже содержит оба обработчика; существующий RTK `PreToolUse` сохранён. Этот файл исключён из Git, поэтому в другом checkout обработчики нужно добавить отдельно. Для каждого события добавьте в его массив следующий элемент, не заменяя существующие hooks:

```json
{
  "matcher": "^(Bash|apply_patch|Edit|Write)$",
  "hooks": [
    {
      "type": "command",
      "command": "/usr/bin/python3 \"$(git rev-parse --show-toplevel)/.codex/hooks/validate_changes.py\"",
      "timeout": 600
    }
  ]
}
```

Для `PreToolUse` достаточно `timeout: 30`; для `PostToolUse` можно добавить `statusMessage` и `additionalContextLimit: 2500`, как в текущей локальной конфигурации. Перезапустите Codex и проверьте доверие к изменённым hooks через `/hooks`. Доверие к проекту и ограничения управляемой среды остаются в силе. Формат событий и обратной связи описан в [официальной документации](https://learn.chatgpt.com/docs/hooks).

Состояние и журналы в `.codex/hook-state/` локальные и исключены из Git. Не включайте их в коммиты: вывод компилятора может содержать фрагменты исходников. Для одного вызова Pre/Post нужны одинаковые `session_id` и `tool_use_id`.

## Проверка обработчика

```sh
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 .codex/hooks/test_validate_changes.py -v
```

Проверки используют временные каталоги и не запускают Gradle, npm или браузеры. Живое подключение к агентному циклу проверяйте после доверия к hooks: при следующей правке исходников агент должен получить результат соответствующей команды, а при чтении неизменённых файлов нового запуска не будет.
