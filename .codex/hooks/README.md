# Хук компиляции

`compile.sh` — Bash-хук для `PostToolUse` после `Write`, `Edit` и `apply_patch`.
Получает пути из JSON события, выбирает команду и возвращает результат агенту.
Для patch учитываются добавление, изменение, удаление и перенос файлов; каждый
затронутый модуль компилируется один раз за вызов. ESLint проверяет каждый изменённый существующий файл фронта.

- Java в `src/` модулей `rfr-auth`, `rfr-api`, `rfr-e2e`: `./gradlew -q :<модуль>:compileTestJava`.
- `.ts`/`.tsx` в `rfr-gql-client/src/`: локальные ESLint (путь файла относительно фронта, предупреждения недопустимы) и `tsc --noEmit` из каталога фронта.
- Остальные файлы пропускаются. Правки через shell требуют явного запуска проверок агентом.
- При ошибке хук выводит последние 60 строк диагностики в stderr и завершается с кодом 2.
- Снимков, состояния, блокировок и отдельных журналов нет. E2E-тесты не запускаются.

ESLint добавлен пользователем в рамках домашнего задания.
Полный lint модуля и сборка Vite выполняются отдельно, как и в CI.

Нужны Bash, `jq`, JDK 25, Node.js в PATH и установленные зависимости фронта.
На macOS хук выбирает JDK 25 через `/usr/libexec/java_home`. Если Node.js отсутствует в PATH хука, используется установленный Node 24 из `~/.nvm/versions/node/`.
Для хука компиляции Go и Python не требуются. Автоматическое переписывание RTK отключено; вызывайте `.rtk/rtk` явно, как описано в `RTK.md`.

## Подключение

В [`.codex/hooks.json`](../hooks.json) настроен обработчик компиляции. Конфигурация хранится в Git вместе со скриптом и доступна после клонирования репозитория. RTK `PreToolUse` отключён, чтобы автоматическое переписывание не мешало командным запретам:

```json
{
  "matcher": "^(apply_patch|Edit|Write)$",
  "hooks": [{
    "type": "command",
    "command": "bash \"$(git rev-parse --show-toplevel)/.codex/hooks/compile.sh\"",
    "timeout": 600,
    "statusMessage": "Проверка компиляции"
  }]
}
```

Этот элемент размещается в `hooks.PostToolUse`. Путь к скрипту определяется от корня Git-репозитория, поэтому запуск Codex из подкаталога также поддерживается.

После клонирования подготовьте перечисленные выше зависимости и откройте проект в Codex. Для загрузки новой конфигурации перезапустите сессию. Проектный слой `.codex/` должен быть доверенным; новое или изменённое определение хука также требует проверки и подтверждения доверия. В CLI это можно сделать через `/hooks`. Подробнее — в [документации Codex](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks).

Старые исходники и настройки сохранены в `.codex/hook-state/backups/` и исключены из Git.

Проверка синтаксиса: `bash -n .codex/hooks/compile.sh`.
