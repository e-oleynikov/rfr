# rfr-test-data v1

- Перед изменениями прочитай инструкции rfr-e2e и существующие фикстуры нужного предусловия.
- Генерируй уникальные данные для каждого теста через RandomDataUtils; не используй общие логины и изменяемые записи между тестами.
- Создавай минимальное число пользователей и связей, необходимое для сценария; связанные пользователи также должны быть уникальны.
- Владелец созданных ресурсов — дерево декораторов UserFixture; TestUser хранит данные, но не управляет их жизненным циклом.
- Каждый декоратор владеет вложенной фикстурой и своими связанными пользователями; регистрируй ресурс до операции, способной частично завершиться.
- Корень дерева сохраняется в JUnit Store до create(); close() очищает связанные ресурсы в обратном порядке, затем вложенную фикстуру.
- Используй TearDown для попытки всех шагов очистки с сохранением ошибок; удаляй только принадлежащие тесту данные по точным уникальным логинам.
- Для новой связи добавляй значение Relation: оно определяет статус, направление и список TestUser; используй UserWithRelationsFixture(origin, relation, count). Иное предусловие с отдельным жизненным циклом оформляй отдельным декоратором. Композиция — в UserRequest.fixture(), не в UserExtension или SingeUserFixture.
- Дополнительных пользователей создавай через SingeUserFixture; сохраняй их в соответствующем списке TestUser после успешного создания связи.
- SQL вызывается только объектами строк и коллекций строк в data/db; тексты запросов храни в src/test/resources/sql и передавай значения параметрами.
- TestUserRepository координирует объекты data/db и транзакции; в тестах, расширениях и фикстурах SQL запрещён.
- Если предусловию нужен API-профиль, создавай его явно через createApiProfile до создания связей; не рассчитывай на первый вход через UI.
- Для связи явно определяй requester, addressee и статус; для исходящего приглашения requester — основной пользователь, статус — PENDING.
- Пул заранее заведённых пользователей допустим только там, где создать пользователя нельзя; зафиксируй причину, исключительное выделение на тест и возврат состояния после него.
- Проверяй наличие подготовленных данных и направление связей, а после закрытия дерева — отсутствие созданных профилей и связей; для @User используй существующие пробы EngineTestKit.
